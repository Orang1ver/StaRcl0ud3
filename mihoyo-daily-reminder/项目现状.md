# 米哈游每日助手 · 项目现状（给新对话的交接说明）

> 这份是「米哈游每日助手」的当前状态。**新开一个对话时，先读这份 + `AGENTS.md`**，
> 就能接上之前的设计决定，不用重新问一遍。
> 最后更新：2026-09-14

## 一句话

给 **原神 / 崩坏：星穹铁道 / 绝区零** 做的每日任务助手：一个桌面程序 + 每天 23:30 的提醒弹窗，
共用同一份打卡数据；三款都清完有庆祝，连续打卡有奖励（XP / 代币 / 里程碑 / 商店）。

## 有几个入口

| 入口 | 怎么起 | 干什么 |
| --- | --- | --- |
| 桌面程序 | 双击 `米哈游每日助手.exe` | 今天清完没有、标记完成、启动游戏、设置 |
| 23:30 提醒 | `米哈游每日助手.exe --reminder`（计划任务里） | 三款都清完弹「恭喜完成」窗口，否则弹提醒窗口 |
| 看门进程 | `米哈游每日助手.exe --watch -ProcessNames YuanShen,StarRail,...` | 盯游戏进程，退出后回来提醒/唤起程序 |
| 备用 | `desktop-app.cmd` | exe 跑不起来时的入口 |

**exe 是独立宿主**：它把 Windows 自带的 PowerShell 引擎装进自己进程里跑脚本
（`build\Launcher.cs`），所以任务管理器里看到的就是「米哈游每日助手」，不会冒出 `powershell.exe`。
宿主兼容老快捷方式残留的 powershell 参数（`-NoProfile` / `-WindowStyle` / `-File …` 会被忽略），
**它调用的 `.ps1` 必须带 UTF-8 BOM**。

## 现在做到哪了

- 桌面程序：今日委托卡片（标记完成 / 启动 / 运行中状态）、打卡记录（连击/徽章墙/日历）、
  奖励中心（XP/代币/里程碑/商店/撤销兑换）、设置（提醒时间、数据、快捷方式）
- 提醒弹窗：卡片式勾选、稍后提醒（独立进程）、三款全清的庆祝层（彩带 + 徽章）；
  三款早就清完的那天，23:30 弹的也是这个庆祝层，只是标题文案换成道喜
  （看门进程那边传 `-SkipWhenDone`，免得刚恭喜完又恭喜一次）；
  设置页「预览恭喜弹窗」= `-ForceCongrats`，只看样子、不读也不写打卡记录
- 弹窗的置顶是**软置顶**（`lib.ps1` 的 `Enable-ReminderSoftTopmost`）：弹出来时在最上面，
  你一切到别的窗口它立刻取消置顶让开，点回来再抬上来。**用户明确说过「强制置顶很烦」**，
  别改成 Win32 `SetWindowPos` 定时重抬的那种硬置顶。桌面程序主窗口**不**置顶。
- **游戏退出后回来提醒**：启动结果窗口里可选「重新弹提醒 / 打开桌面程序 / 不用管」，
  设置存 `watch.json`；看门进程有锁（同时只跑一个）、先等游戏起来（默认 3 分钟）、
  连续两次看不到才算退出、至少跑 90 秒、最多盯 6 小时
- **启动方式分两路**（`lib.ps1` 的 `Get-XxmiLaunch` / `Start-ReminderGame`）：
  - 原神 → 官方 `YuanShen.exe`，直接启动
  - 崩坏：星穹铁道 → **XXMI 的 SRMI**；绝区零 → **XXMI 的 ZZMI**
    （`XXMI Launcher.exe --nogui --xxmi SRMI|ZZMI`）。用户明确要求：官方 exe 直拉不会加载模组，
    这两款必须走 XXMI。XXMI 没装、或它配置里没启用对应导入器时，自动退回官方 exe
  - 「装没装」仍按官方目录判断（`Star Rail Game` / `ZenlessZoneZero Game`）；
    `Get-GameList` 每项多了 `Via`（界面写「XXMI · SRMI」）、`ExeArguments`、`OfficialPath`、
    `WatchNames`（走 XXMI 时 = 游戏进程 + `XXMI Launcher`）
  - XXMI 目录默认 `D:\XXMI launcher`；装在别处就在脚本目录写一行 `xxmi-path.txt` 覆盖
  - 看门进程盯 `WatchNames` 而不是单看游戏进程：XXMI 启动后**自己会一直活着**（2026-09-20
    的日志：注入完走 `WaitForProcess`，游戏关了才 `App Exit`），所以 XXMI 在 = 游戏还没退。
    两个一起盯最稳：既不会在"启动器刚退、游戏刚起来"的空档误判成游戏已退，也不怕哪天
    XXMI 改成启动完就退出
- 打卡口径：**每日 04:00 刷新**（0:00–3:59 仍算前一天）
- 单实例：互斥体 + 按窗口标题找进程，第二个实例会提示「已经在运行了」

## 数据结构

- `history.json`（不进仓库）：`days{ 日期 → ['原神','崩坏：星穹铁道',…] }`、`redemptions[]`
- `watch.json`（不进仓库）：`enabled / mode(ask|app|none) / maxHours / minSeconds / pollSeconds / graceSeconds`
- `rewards.json`（进仓库）：任务分值、全清奖励、连击倍率、里程碑、商店

## 用户电脑上的实际情况

- 游戏装在哪：`D:\miHoYo Launcher\games\...`（`lib.ps1` 的 `Get-LauncherRoot` 会从注册表找）
- XXMI Launcher 装在哪：`D:\XXMI launcher`（`Resources\Bin\XXMI Launcher.exe`）；
  配置 `XXMI Launcher Config.json` 里 SRMI / ZZMI / GIMI 都已启用，
  SRMI 和 ZZMI 都指向 `D:\miHoYo Launcher\games\...`
  - 桌面上的 `SRMI Quick Start.lnk` / `ZZMI Quick Start.lnk` 就是同一套参数，可对照
  - 排查启动方式：`desktop-app.ps1 -CheckOnly` 会逐款打印 `[XXMI · SRMI] ... --nogui --xxmi SRMI`
- 桌面快捷方式：`桌面\🛠 游戏工具\米哈游每日助手.lnk`（指向 exe、无参数）+ 开始菜单一份
  - 注意：快捷方式里**参数必须是空的**；老版本留下的 powershell 参数会让双击"没反应"
    （宿主现在会忽略它们，但新建快捷方式时别再写参数）
- 提醒计划任务**目前没注册**（用户之前删过）；要恢复用 `setup.ps1 -Time 23:30` 或在设置页点「保存时间」

## 容易踩的坑

- 宿主给脚本传参时是**命名参数**（`build\Launcher.cs` 自己解析 `-Name value`）；
  直接 `AddArgument("-Name")` 会被 PowerShell 当位置参数，参数名失效。
- 后台任务（`--reminder` / `--watch`）出错**不弹错误框**，只写日志
  `%TEMP%\mihoyo-daily-reminder.log` —— 不然它们卡在对话框上会占住文件。
- 改动过 exe 之后：`米哈游每日助手.exe` 是**提交进仓库的**，改完要 `build\build-exe.ps1` 重新编译并一起提交。
- 跑自检要传 `-ProjectRoot`；`build\test-rewards.ps1` 会比对 `history.json` 的 SHA256，不会碰真实数据。
- 桌面/开始菜单快捷方式的路径里带 emoji 时，`WScript.Shell` 读写会失败 ——
  要"先建到桌面再用 PowerShell Move-Item 搬进去"。
